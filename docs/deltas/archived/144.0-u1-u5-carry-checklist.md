## Wybrane / odrzucone / dlaczego

**Wybrane (węższe z pary U1+U5):** dwie tabele per tenant w jednym plasterze, bo kolejka trzyma je razem.

1. `field_carry_forward` — snapshot pola z wyceny na zlecenie. Klucze allowlista: `incoterm` | `trade_side` | `named_place`. Wartość to tekst, nie kwota. Zmiana = nowy wiersz + `superseded_by`. API dostaje już odczytane pola (serwis nie importuje quotations). POST `/field-carry-forwards` z `quotation_id` + `shipment_id` + mapa pól. Ten sam klucz bez zmiany = ten sam bieżący wiersz (no-op).
2. `document_checklist_rule` — `(incoterm, trade_side, mode)` → `document_kind` + `blocks_dispatch`. `mode`: `ocean` | `road` | `rail` | `air`. `document_kind` to katalog reguły (`commercial_invoice` | `packing_list` | `bill_of_lading` | `export_declaration`), nie `shipment_document.document_kind` (`noted`/`attached`/`other`). GET filtr SQL po trójce. Flaga `blocks_dispatch` jest daną — egzekucja dispatch = leftover I1.

UI `/quotations` (Incoterms już tam). `SHIPPED_CHARGE_ROUTES["144.0"]` = `/quotations`. OpenFGA: `can_manage_quotations` (reguły) i `can_manage_shipments` (przeniesienie). Migracja `084_carry_checklist`.

**Łowca:** ISTNIEJE `quotation.incoterm` / `trade_side` / `named_place` (137.0). ISTNIEJE `shipment` z FK wyceny. ISTNIEJE GLOSSARY `field_carry_forward`. ISTNIEJE `shipment_document.document_kind` noted/attached/other — **inny** katalog. BRAK tabeli przeniesienia. BRAK reguły checklisty. BRAK cichego overwrite.

**Odrzucone:**

- Cichy UPDATE `shipment` z pól wyceny.
- Kwota / waluta / waga / HS w tym plasterze (karta U1 ma mapę; tu trzy pola Incoterms).
- Booking / dispatch / FV — tych tabel nie ma.
- Import serwisu quotations w shipments i odwrotnie.
- C8 polisa podwykonawcy.
- Python liczący dni robocze (U4) albo blokujący dispatch.
