## Wybrane / odrzucone / dlaczego

**Wybrane (węższe z G2.5–G2.18):** jedna tabela `tender_matrix_cell` per tenant — **komórka matrycy z kwotą Decimal z P**, nie mapowanie kolumn przez LLM i nie druga marża. Wiersz = `tender_id` (FK tenanta do `tender`) + `cell_code` (snake 2–32) + `amount` (`Numeric(14,4)` > 0, Decimal, zakaz float) + `currency` (`CHAR(3)`) + `source_ref` (`tenant:manual` albo `fixture://tender-matrix-cell/…`). Operator wkleja kwotę z P; serwis nie czyta `charge` / `rate_line`. Zły kod → 400 (`komórka`). Zła kwota / float / bool → 400 (`kwota`). Obce `source_ref` → 400 (`obce`). Unique `(organization_id, tender_id, cell_code)`. GET listy SQL. Serwis nie importuje tenders / charges / rate_lines / quotations. API składa odczyt nagłówka (`TenderService.get_board`). UI `/tender-matrix-cells` z `<Money/>` na liście, bez `sum()` w JS. `SHIPPED_CHARGE_ROUTES["174.0"]` = `/tender-matrix-cells`. OpenFGA: `can_manage_tender_matrix_cells`. Migracja `114_tender_matrix_cell`. Marża zostaje na `charge`.

**Łowca:** ISTNIEJE `charge` — jedyna marża; **nie** druga tabela marży. ISTNIEJE `rate_card` / `Money` — Decimal + waluta; **reuse wzorca walidacji**, nie nowy parser float. ISTNIEJE `tender` — nagłówek; **nie** dokładamy komórek jako JSON tam. BRAK `tender_matrix_cell`. BRAK `/tender-matrix-cells`.

**Odrzucone:**
