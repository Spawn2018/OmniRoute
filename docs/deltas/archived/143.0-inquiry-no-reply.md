## Wybrane / odrzucone / dlaczego

**Wybrane (węższe z kolejki N5):** kolumna `no_reply_after` (date, nullable) na istniejącej `carrier_inquiry`. Operator podaje datę kalendarzową przy zapisie albo zostawia pusto. Lista `/carrier-inquiries?silent=overdue` — wiersze z datą `< bieżący dzień` (filtr w SQL). Notice: nowy kind `no_reply` na `operator_notice` (CHECK), **tylko POST operatora** z `source_ref` i treścią; `subject` zostaje w treści, nie nowa kolumna FK. UI `/networks`: data + lista przeterminowanych. `SHIPPED_CHARGE_ROUTES["143.0"]` = `/networks`. OpenFGA bez nowej relacji.

**Łowca:** ISTNIEJE `carrier_inquiry` (statusy, lane). ISTNIEJE `operator_notice` (kind tylko `manual`). BRAK daty ciszy. BRAK kind `no_reply`. BRAK filtra overdue.

**Odrzucone:**

- Auto-INSERT `operator_notice` (AGENTS M-34: zakaz auto-INSERT).
- Auto-send ponaglenia / Graph / mailto z crona.
- Silnik dni roboczych U4 w Pythonie — data jest polem, nie wyliczeniem.
- Nowa tabela SLA.
- Mutacja `no_reply_after` w miejscu bez nowego wiersza inquiry — zmiana daty = PATCH tego wiersza (data nie jest kwotą).
