## Wybrane / odrzucone / dlaczego

**Wybrane (węższe z leftover U3 cyfra kontrolna IATA):** token HAWB/MAWB i pule M-03 już są. Live IATA zostaje. Żywy plaster: **bramka w domenie na wklejonym `mawb_no`**, gdy po trimie ma kształt IATA `3 cyfry`, opcjonalny myślnik, `8 cyfr`. Ostatnia cyfra = reszta z dzielenia siedmiocyfrowej serii przez 7 (IATA Resolution 600a; prefiks linii nie wchodzi do reszty). Zła cyfra → 400 (`cyfra`). Kształt inny niż IATA (pula `prefiks`+4, token 209.0, HAWB) zostaje bez tej bramki. `null` i pusty trim zostają `null`. Serwis `shipment_legs` woła bramkę tylko dla mastera, po `require_air_waybill_no`. Nadanie SQL z 619.0 nie przechodzi przez domenę — pula nie dostaje cyfry. Bez nowej kolumny, bez CHECK w bazie (prefiks z samych cyfr o długości 7 dałby 11 cyfr i CHECK odrzuciłby nadanie). UI zostaje `/air`. `SHIPPED_CHARGE_ROUTES["622.0"]` = `/air`. OpenFGA bez nowej relacji. Marża zostaje na `charge`. Zero float. Zero HTTP IATA.

**REQUIREMENT:** leftover PLAN U3 „cyfra kontrolna IATA → 622.0”. Metoda: IATA Resolution 600a, seria 7 cyfr modulo 7. Źródło: `docs/PLAN-REALIZACJA.md` wiersz U3; wzór bramki wejścia: `require_container_no` w `app.domain.container` (inny algorytm, ten sam rodzaj bramki).

**Łowca:** ISTNIEJE `require_air_waybill_no` (token 2–32). ISTNIEJE `020-12345675` w teście rodzaju — seria `1234567` mod 7 = 5, więc ten token już jest zgodny. ISTNIEJE pula SQL `MAX`+1. ISTNIEJE cyfra ISO 6346 na kontenerze. BRAK bramki modulo 7 na MAWB. BRAK live IATA.
