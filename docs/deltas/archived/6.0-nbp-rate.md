## Ustalenia

- Żywy ID: **M-23**. Token: `nbp_rate`. Archiwum M-07 „waluty i czas” nie używa numeru M-07 w kodzie.
- Fala 3 „Waluty w ofercie” (archiwum M-23) = późniejszy plaster na `quotation`, nie drugi katalog FX.
- `currency`: ISO 4217, 3 litery A–Z. Inne = `InvalidCurrency`. Brak wiersza PLN (NBP nie kwotuje PLN/PLN).
- `mid`: `Numeric(14,4)` — skala tabeli A NBP. Nigdy float.
- `source_ref` obowiązkowy; ręczny wpis = `tenant:manual`; fixture = `nbp:A:<date>:<table_no>`.
- Unikat `(organization_id, currency, rate_date)`.
- `resolve`: SQL `rate_date <= on_date` ORDER BY `rate_date` DESC LIMIT 1; pusto = `UnknownNbpRate`.
- OpenFGA: `can_manage_nbp_rates` = `member`. Brak tuple na wiersz.
- RLS FORCE + test izolacji dwóch organizacji.
- Job operatora: `/nbp-rates` — DataTableShell, dodanie, pole resolve (waluta + data).
- import-linter: `app.services.nbp_rates` niezależny BC. `quotations` / `charges` / `rate_lines` / `extraction` nie importują.
- Migracja `018_nbp_rate_rls` (w górę i w dół).
- LLM nie liczy. `charge` = marża zostaje.

## Schemat

`nbp_rate`: `id`, `organization_id`, `currency` CHAR(3), `rate_date` DATE, `mid` Numeric(14,4), `source_ref`, timestamps.
