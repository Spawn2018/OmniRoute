## Zakres
- Tożsamość: JWT HS256 (`Authorization: Bearer`). Claims `sub` = `app_user.id`, `org` = `organization_id`.
- API odrzuca brak/nieważny token (401). Tenant i użytkownik **tylko z claims** — `X-Organization-Id` / `X-User-Id` nie ustalają kontekstu.
- Hello login: `POST /api/v1/session/token` z id z seeda; weryfikacja `app_user` (bez hasła, bez IdP).
- OpenFGA = autoryzacja; RLS `app.current_org` z claims.
- Frontend: jeden token w localStorage; kontekst tenanta z claims (bez drugiego table engine).
