## Wybrane / odrzucone / dlaczego

**Wybrane (węższe z D2):** jedna tabela `shipment_package` per tenant na **zleceniu**. Czwarty szczebel statusu SPEED (przesyłka / paczka / punkt / trasa): `shipment` + `stop` + `trip` już są; ten plaster dodaje paczkę. Wiersz = `package_code` (snake 2–32) + FK złożone do `shipment` + `stop_id` (ten sam `shipment`) + `package_status` (`noted` | `at_stop` | `in_transit` | `delivered`) + `scan_token` + `source_ref`. POST skanu: token `omni://shipment-package/{package_code}` albo `fixture://omni-qr/` + ten sam kod; inny kod kreskowy → 400 (detail zawiera `QR Omni`). `stop` nie z tego zlecenia → 400 (detail zawiera `trasy`). GET listy SQL. API składa odczyt `shipment` i `stop`; serwis paczki nie importuje shipments / stops / geography / charges. UI `/shipment-packages`. `SHIPPED_CHARGE_ROUTES["156.0"]` = `/shipment-packages`. OpenFGA: `can_manage_shipment_packages`. Migracja `096_shipment_package`.

**Łowca:** ISTNIEJE `shipment` / `shipment_document` / `tracking_event` — **inny** agregat (zlecenie, wskazanie dokumentu, log zdarzenia), nie sztuka paczki. ISTNIEJE `stop` / `trip` — punkt i trasa, nie paczka. ISTNIEJE `groupage_line` — katalog linii, nie skan. BRAK `shipment_package`. BRAK `/shipment-packages`. BRAK skanu QR Omni.
