## Wybrane / odrzucone / dlaczego

**Wybrane (węższe z leftover „SQL przy FV”, po T7c 617.0):** na `shipment` nie ma kolumn `etd` / `loading_date` / `unloading_date` / `invoice_date` (odczyt modelu). Składanie offsetu U4 z kwotą zostaje. Żywy plaster: **funkcja SQL** `charge_sell_in_pln(charge_id, on_date)` w bazie. Waluta `PLN` zwraca `sell_amount` bez kursu (`nbp_rate` nie trzyma PLN). Inna waluta: `sell_amount * mid_rate` z `nbp_rate` tego tenanta na `on_date`, typ `numeric`. Brak wiersza kursu → 400 (`kurs`). Wynik nie jest kolumną i nie jest drugą marżą. Python nie mnoży. GET na istniejącym `/charges`. Serwis `charges` nie importuje `app.services.nbp_rates`. OpenFGA bez zmian.

**CONFIRMED:** brak dat bazowych na `shipment` — `backend/app/models/shipment.py` nie ma tych pól. Kurs: `nbp_rate.rate_date` + `currency`, `currency <> 'PLN'`.

**Łowca:** ISTNIEJE `charge.sell_amount` i `nbp_rate`. ISTNIEJE `fx_rate_day` (data, nie kwota). BRAK funkcji mnożącej w SQL.
