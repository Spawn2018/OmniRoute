## Wybrane / odrzucone / dlaczego

**Wybrane (węższe leftover CT1 / pin 2026-09-08c: katalog HITL linii zamówienia zakupu jako dane; nie ASN i nie auto shipment):** leftover ASN / EDI 856 parked. leftover auto-create `shipment` (U1) parked. leftover CT8 AIS live parked (TO_VERIFY licencja). leftover CI1 extract parked. leftover live p44 parked. leftover qty jako float parked na stałe. Żywy plaster: **nowa tabela** `po_line` per tenant w **tym samym BC** `purchase_orders` — HITL katalog linii SKU na istniejącym nagłówku, nie awizo i nie zlecenie. GLOSSARY: **linia zamówienia zakupu** = `po_line` (nie kolumny na `purchase_order`, nie `shipment_package`, nie `commodity_code`). Wiersz = `line_code` (snake 2–32) + `purchase_order_id` (złożone FK `(organization_id, purchase_order_id)` → `purchase_order`, ten sam tenant) + `sku_code` (tekst 1–64) + `qty` (`Numeric(14,4)` ≥ 0, Decimal / int / string dziesiętny — **nigdy float**) + `uom_code` (tekst 1–16) + opcjonalne etykiety `plant_label` / `batch_label` / `serial_label` / `coo_label` (tekst 1–128 albo brak; **nie** FK geography / `party` / `commodity_code`) + `source_ref` (`tenant:manual` albo `fixture://po-line/…`). Zero kolumn ASN / `shipment_id` / kwoty / waluty. Operator wpisuje linię na znanym nagłówku; serwis nie woła HTTP, nie woła LLM, nie importuje `shipments` / `charges` / `field_carry_forwards` / `extraction` i nie liczy marży. Katalog unique, POST INSERT, GET lista, bez UPDATE/DELETE. Zły kod linii → 400 (`linia`). Zły SKU → 400 (`sku`). Zła ilość / float → 400 (`ilość`). Zła JM → 400 (`jm`). Zła etykieta → 400 (`zakład` / `partia` / `seria` / `kraj`). Obce `source_ref` → 400 (`obce`). Nieznany albo cudzy `purchase_order_id` → 404 (`nieznane zamówienie`) — RLS ukrywa wiersz tenanta B. Body z ASN/kwotą (`asn`, `shipment_id`, `amount`, `currency`, `buy_amount`) → 422 (`extra=forbid`). Unique `(organization_id, purchase_order_id, line_code)` i `(organization_id, source_ref)`. GET listy SQL. UI `/po-lines`. `SHIPPED_CHARGE_ROUTES["277.0"]` = `/po-lines`. OpenFGA: **reuse** `can_manage_purchase_orders` — ta sama relacja co 276.0, bo linia jest jobem tego samego katalogu CT1, nie nowym obiektem AuthZ; nowa relacja byłaby teatrem. Migracja `210_po_line` (po `209_purchase_order`). Job OPS 122. Deny-list: `extraction-no-rates` już ma `app.services.purchase_orders` / `app.models.purchase_order`; dodać `app.models.po_line`. Marża zostaje na `charge`. To nie jest ASN i nie jest live widoczność.

**Łowca:** BRAK tabeli `po_line`. BRAK `sku_code` / `uom_code` / `coo_label` w schemacie. ISTNIEJE `purchase_order` 276.0 — nagłówek, **ten sam BC, FK OK**. ISTNIEJE `shipment` / `shipment_package` — zlecenie i paczka, **nie** linia PO (nie rozszerzać, nie FK). ISTNIEJE `commodity_code` — HS/CN, **nie** SKU. ISTNIEJE `field_carry_forward` U1 — oferta→zlecenie, **nie** PO. ISTNIEJE `edi_message` — komunikat na zleceniu, **nie** ASN 856. ISTNIEJE `lane_km` — Decimal ≥ 0 bez float, **wzorzec qty**, inny job. PODOBNE: dziecko z FK tenanta jak `tender_lane` / `consignment`; qty jak `lane_km` / `vgm_kg`. Nie wyodrębniać wspólnej warstwy (drugie, nie trzecie powtórzenie).
