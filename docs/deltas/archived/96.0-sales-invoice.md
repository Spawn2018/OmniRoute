**Status:** Zamknięty `/noc` 2026-09-03. Ten sam żywy ID **M-40**. Nie F9.1.

## Wybrane / odrzucone / dlaczego

**Wybrane:** tabela `sales_invoice` per tenant na **zleceniu**. Operator zapisuje, że zafakturował robotę (`issued` / `noted` / `other`) z `invoice_ref` (wpisany numer dokumentu, nie licznik) i `source_ref`. Wiele wierszy na jedno `shipment` (zaliczka i reszta bez silnika numeracji). API składa: odczyt `shipment`, zapis faktury. Serwis faktury nie importuje `shipments` / `charges` / `quotations`. Tablica 33.0 przestaje udawać, że `sell` z `charge` to faktura. Kwoty zostają na `charge`. Wzorzec jak S33. Zero KSeF. Zero odejmowania.

**Łowca:** ISTNIEJE 33.0 `/invoices` + `fetchCharges` / `sell_amount` / `<Money/>`. BRAK tabeli `sales_invoice` / `invoice` / KSeF w modelach. PODOBNE: 95.0 `edi_message`; 93.0 `operational_exception`; 92.0 `shipment_document`. Dwa joby (opłata vs faktura) = `/charges` vs `/invoices`. M-41 `/quote-invoices` zostaje tablicą rozliczenia.

**Odrzucone:**

- KSeF / XML / FA(3) — S35.
- Kopia `sell_amount` / `buy_amount` / marży na wierszu faktury — druga prawda obok `charge`.
- JS odejmujący buy/sell.
- LLM piszący treść faktury.
- Licznik `GD/2026/…` — leftover S8.
- Unikat jeden wiersz na zlecenie — za ciasno na zaliczkę; S43 to zbiorcze FV, nie ten plaster.
- Faktura na `quotation` zamiast `shipment`.
- Auto-INSERT przy zapisie zlecenia albo z `charge`.
- Tabela rozliczenia M-41.
- Bajty / PDF / druk.
- F9.1.

## Zakres

1. Migracja `054_sales_invoice_rls` (po `053_edi_message_rls`): tabela `sales_invoice` z RLS ENABLE+FORCE; FK tenanta do `shipment`.
2. `GET/POST /sales-invoices` — OpenFGA `can_manage_sales_invoices` = member. POST: `{shipment_id, invoice_kind, invoice_ref, source_ref}`. Nieznane zlecenie → 404. Zły kind / pusty ref → 400.
3. UI `/invoices`: lista wierszy tabeli + „Zapisz fakturę”. `data-sales-invoice="board"` zostaje. Lista **nie** idzie z `fetchCharges`. Linki do `/charges` i `/finance` zostają. `SHIPPED_CHARGE_ROUTES["96.0"]` = `/invoices`. Asercje 33.0 bez `ksef` / odejmowania / `CatalogCreateForm` zostają; `fetchCharges` na tej tablicy znika.
4. Test izolacji. `just api-types`. How-to `docs/operator/faktura.md`.

## Ustalenia

- Token: `sales_invoice` (tabela). How-to: `faktura.md`.
- `invoice_kind` CHECK: `issued` | `noted` | `other`.
- `invoice_ref`: tekst operatora, max 64, po trim niepusty. Bez unikatów — nie silnik numeracji.
- `source_ref`: `fixture://sales-invoice/` albo `tenant:manual`. Pusty po trim = 400. Max 256.
- Serwis bez `httpx` / `requests`. ExtractionService nie importuje faktur.
- LLM nie liczy i nie pisze faktury. `charge` zostaje prawdą o marży. HITL extract bez zmian.
- Formularz: obiekt `draft` + siatka, nie `CatalogCreateForm` (próg `just dup` 3%).

## Schemat

`sales_invoice` (nowa): `id`, `organization_id`, `shipment_id`, `invoice_kind`, `invoice_ref`, `source_ref`, timestamps, `created_by`. FK tenanta do `shipment`. Indeks org+shipment.
