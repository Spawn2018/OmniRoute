# Plaster 532.0 · O7 — filtr `country_code` na liście agentów (API)

**Spec źródłowa:** [PLAN-REALIZACJA.md](../../PLAN-REALIZACJA.md) § O7 · po O4 [138.0](../archived/138.0-inquiry-mail-draft-batch.md) · UI 141.0 [141.0-party-country-filter.md](../archived/141.0-party-country-filter.md)

**Zależy od:** `party.country_code` (M-10) · `network_member.party_id` (O0 / 130.0) · `/networks` (M-12)

## Wybrane / odrzucone / dlaczego

- **Wybrane:** param `country_code` (ISO 3166-1 alpha-2) na istniejącym `GET /api/v1/networks/{network_id}/members`. Postgres JOIN `network_member` × `party` po `(organization_id, party_id)` + filtr `party.country_code`. Pusty / brak parametru = pełna lista. `NL` = agenci Holandii (SHA→RTM). Zero migracji.
- **Wybrane:** UI `/networks` woła API z parametrem (queryKey z filtrem). Wyświetlanie kraju nadal z `party.country_code` (mapa z GET `/parties`) — **nie** druga kolumna DB.
- **Wybrane:** walidacja przez `normalize_country_code` (domena party) → 400 przy złym tokenie (`N`, `12`, pusty po trim gdy podany jako nie-ISO).
- **Odrzucone:** nowa kolumna kraju na `network_member` / druga tabela (`REJECTED` — PLAN: „Nie druga kolumna kraju”).
- **Odrzucone:** scrape / live HTTP / float / marża / O8 group-by (`REJECTED` na tym wierszu).
- **Odrzucone:** import `PartyService` w `NetworkService` (`REJECTED` — BC; JOIN modelu w repozytorium / walidacja w API).

**Łowca:** ISTNIEJE `party.country_code` (`backend/app/models/party.py`). ISTNIEJE lista członków `GET …/members` (`backend/app/api/networks.py`). ISTNIEJE UI filtr kliencki 141.0 (`membersForCountry` + `partyCountryMap` w `frontend/src/lib/networks-api.ts`, ekran `frontend/src/features/networks/catalog-page.tsx`). BRAK query `country_code` na API members. BRAK JOIN filtrującego w `NetworkMemberRepository.list_for_network`.
