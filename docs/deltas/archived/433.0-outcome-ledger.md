## Wybrane / odrzucone / dlaczego

- **Wybrane:** jedna tabela `outcome_ledger` per tenant — append-only HITL. Wiersz = `target_bc` (snake 2–32) + `entity_id` (UUID jako dana, bez FK) + `suggestion_id` (UUID jako dana, bez FK do `suggestion_ledger`) + `outcome_kind` `eta|rate|route|other` + `actual_value` (`Numeric(14,4)`, zakaz float) + `source_ref`. Operator wpisuje, co się naprawdę stało. Serwis nie woła LLM i nie liczy CRPS/MAE/Brier.
- **Wybrane:** `suggestion_id` jako dana, nie FK — złączenie z AI1.0 zostaje w AI2, nie w tym plasterze. Ten sam rygor co `entity_id` na 432.0.
- **Odrzucone:** kolumna CRPS/MAE/Brier — to AI2, liczone ze złączenia, nie wpisane.
- **Odrzucone:** rozszerzenie `suggestion_ledger` albo `prediction_ledger` — tu fakt, nie podpowiedź i nie wpisana metryka.
- **Odrzucone:** `counterfactual_run` / `benefit_ledger` / słowniki AI1.4 — kolejne wiersze Fali AI.
- **Odrzucone:** trzy BC piszące do substratu — warunek końca fali AI1, nie tego plastra.
- **Odrzucone:** FK · JSON payload · UPDATE/DELETE · kwota / marża / float · zapis LLM.

**Łowca:** PODOBNE `suggestion_ledger` (gdzie + kind). PODOBNE `prediction_ledger` (Decimal jako dana). PODOBNE `intervention_outcome` (inny BC, kind wyniku naprawy). BRAK `outcome_ledger`.
