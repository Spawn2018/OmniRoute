# Plaster 100.0 · S38 koszt pieniądza (M-43)

**Spec źródłowa:** [docs/spec/money-cost.md](../../spec/money-cost.md) · [docs/PLAN-REALIZACJA.md](../../PLAN-REALIZACJA.md) § Kolejka S38  
**Zależy od:** 6.0 `nbp_rate` · 99.0 `bank_payment` · 36.0 tablica `/money-cost` · 0.3 RLS · 0.4 OpenFGA

**Status:** Zamknięty `/noc` 2026-09-03. Ten sam żywy ID **M-43**. Nie F9.1.

## Wybrane / odrzucone / dlaczego

**Wybrane:** tabela `money_cost` per tenant. Operator zapisuje, że ta płatność stoi przy tym kursie NBP (`bank_payment_id` + `nbp_rate_id` + `source_ref`). Kwoty zostają na `charge`. Kurs zostaje na `nbp_rate`. Tablica 36.0 przestaje udawać, że `buy` + `mid` to koszt pieniądza. API składa: odczyt płatności, odczyt kursu, zapis wiersza. Serwis kosztu nie importuje `bank_payments` / `nbp_rates` / `charges`. Wiele wierszy na jedną płatność (kolejne tabele A). Unikat pary `(organization_id, bank_payment_id, nbp_rate_id)`. Wzorzec jak S37.

**Łowca:** ISTNIEJE 36.0 `/money-cost` + `fetchNbpRates` / `fetchCharges` / `buy_amount`. ISTNIEJE 6.0 `nbp_rate` (`resolve` po walucie+dacie, nie get po id). ISTNIEJE 99.0 `bank_payment`. ISTNIEJE `party.payment_terms_days` poza HTTP. BRAK tabeli `money_cost` / odsetek / WACC. PODOBNE: 99.0 `bank_payment`; 98.0 `quote_invoice_settlement`. Dwa joby (kurs vs koszt) = `/nbp-rates` vs `/money-cost`.

**Odrzucone:**

- Zostawić tablicę z `charge` — to fundament 36.0, nie żywe M-43.
- Mnożenie `buy × mid` w JS albo w Pythonie.
- Kolumna kwoty / `mid` / `buy` na wierszu kosztu.
- WACC / tabela odsetek.
- `payment_terms_days` w tym API — kolumna jest na `party`, nie tu.
- Zapis kursu z `/money-cost` — mutacja zostaje na `/nbp-rates`.
- F9.1.

Asercje 36.0 bez `parseFloat` / mnożenia `mid` / `CatalogCreateForm` zostają; `fetchCharges` na tej tablicy znika.
4. Test izolacji. `just api-types`. How-to `docs/operator/koszt-pieniadza.md`.
