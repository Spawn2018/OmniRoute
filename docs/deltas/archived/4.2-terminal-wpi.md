# Plaster 4.2 · M-05 Geografia (`terminal` + World Port Index)

**Spec źródłowa:** [docs/spec/geography.md](../../spec/geography.md), sekcja 4.2  
**Zależy od:** 0.3 RLS · 0.4 OpenFGA · 0.6 DataTableShell · 4.0 `port` · 4.1 `uq_port_org_id`

**Status:** Zamknięty 2026-09-01. Plan zaakceptowany, kod w repo, `just gate` zielony lokalnie.

## Zakres

Tabela `terminal` (kod ISPS, operator jako tekst) oraz pola World Port Index (NGA Pub 150) na istniejącym `port`. Ingest WPI poza HTTP, pin SHA, CI = fixture. UI `/terminals` (DataTableShell): lista, dodanie, filtr po porcie, resolve ISPS. Kolumny WPI na istniejącym `/ports` — bez trzeciego ekranu.

## Poza zakresem

OSM, geometria poligonowa, strefy czasu dojazdu, `operator_party_id` / M-10, POL/POD w `quotation`, podpięcie `rate_line`, `pg_trgm`, `kind='terminal'` na `location`, pełny dump NGA (~100 kolumn), live fetch NGA/GitHub w requeście, Q2 M-10, M-02 outbox, Auth0, Exit Wave FE, leftovery UI ADR-0003, światowy seed ISPS.

## Ustalenia

- Żywy ID modułu: **M-05**. Brak kolizji z żywym M-07 `rate_line` / M-08 `charge`.
- Terminal to **osobna tabela**, nie `location.kind`. Test `parse_location_kind("terminal")` zostaje odrzutem.
- Operator terminalu = `operator_name` (nullable text). `operator_party_id` dopiero przy M-10.
- Brak `is_official` na terminalu: to nie katalog światowy. `source_ref = tenant:manual`. Brak seedu ISPS w 4.2.
- OpenFGA bez zmian: `can_manage_geography` = `member`, jedna relacja na 4.0–4.2, już w `authz/model.fga`.
- RLS FORCE na `terminal` + test izolacji dwóch organizacji. Runtime `omniroute_app` NOBYPASSRLS. Kolumny WPI siedzą na `port` — istniejąca polityka RLS `port` wystarcza.
- Job operatora w tym plastrze: `/terminals` (DataTableShell) — lista, dodanie, filtr `port_id`, resolve kodu ISPS. Pola WPI tylko jako kolumny odczytu na `/ports`.
- `resolve(isps_code)`: dokładne dopasowanie bez wielkości liter. Nieznany = `UnknownTerminal`. Brak aliasów i `pg_trgm`.
- WPI = ALTER na `port`, nie osobna tabela. Ingest tylko `UPDATE` istniejącego wiersza po znormalizowanym `unlocode`. Nie tworzy portu. Nie nadpisuje `lat`/`lng` ani `source_ref` UN/LOCODE. Dwa wiersze WPI na ten sam kod = błąd domenowy, nie last-write-wins.
- Źródło WPI: NGA Pub 150 (`UpdatedPub150.csv`), plik lokalny + pin SHA w `wpi_source_ref`. Pełnego CSV nie w git. CI = fixture (w tym PLGDY), zero sieci.
- UN/LOCODE w CSV NGA ma spację (`PL GDY`) — ingest zwija do `PLGDY` zanim dopasuje.
- Głębokości w aktualnym CSV NGA są już w metrach — zero konwersji stóp. Numeric, nie float.
- Endpoint `/ports` i `/terminals` nie sięgają po sieć — test skanuje API jak w 4.0.
- `backend/app/services/geography/AGENTS.md`: `app.models.terminal` do dozwolonych; zdjąć zakaz `terminal` / WPI. Ingest nadal bez sieci w serwisie.

## Schemat

`terminal`: `id`, `organization_id`, `port_id`, `name`, `isps_code` (nullable), `operator_name` (nullable text), `lat`/`lng` Numeric nullable, `source_ref`, timestamps.

- FK `(organization_id, port_id)` → `port(organization_id, id)` — nośnik `uq_port_org_id` już jest z 4.1.
- `UNIQUE (organization_id, id)` jako nośnik na przyszłe FK.
- Unikat częściowy `(organization_id, isps_code) WHERE isps_code IS NOT NULL`.
- Unikat `(organization_id, port_id, name)` — dwa terminale bez ISPS przy tym samym porcie nie mogą się nazywać tak samo.

`port` (ALTER): `wpi_number` (nullable, unikat per tenant gdy nie NULL), `harbor_size`, `harbor_type`, `shelter` (text + CHECK ze słownika NGA: Very Small / Small / Medium / Large; typy i shelter jak w `UpdatedPub150.csv`), `channel_depth_m`, `cargo_pier_depth_m` Numeric, `wpi_source_ref` nullable.
