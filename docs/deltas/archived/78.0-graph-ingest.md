## Wybrane / odrzucone / dlaczego

**Wybrane:** ten sam żywy ID **M-32**, ta sama tabela `inbound_message`. Ingest Graph to **zapis już pobranej** wiadomości: `source_ref` zaczyna się od `graph://`, `external_id` (id wiadomości Graph) unikat per tenant. Drugi POST z tym samym `external_id` zwraca istniejący wiersz — lookup przed INSERT, unikat w bazie. Status nadal `draft`. OpenFGA: istniejące `can_manage_inbound_messages`. Ekran `/mail`: formularz ingest Graph (nie IMAP). Serwis nie woła Microsoft Graph i nie send. Sekret Graph **nie** wchodzi do bazy w tym plasterze — HC: poświadczenie tenanta tylko szyfrowane jego kluczem; dziś brak tej kasy = leftover, nie plaintext.

**Łowca:** BRAK `external_id` / `graph://` / klienta Graph. ISTNIEJE: 64.0 `inbound_message` z CHECK `fixture://`|`synth://`. ISTNIEJE: create fixture na `/mail`. PODOBNE: unique pending na decyzji — tu unique `(organization_id, external_id)` gdy niepuste.

**Odrzucone:**

- Live HTTP do Graph (teatr bez umowy tenanta; S21 ten sam zakaz).
- Zapis tokenu Graph w `organization_setting` / kodzie / logach (HC, brak szyfrowania kluczem tenanta).
- Send / `mailto:` (S18).
- IMAP / EmailEngine (S17, nie w tym samym commicie).
- Outbox / M-02 (S16).
