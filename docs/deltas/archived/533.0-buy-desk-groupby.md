## Wybrane / odrzucone / dlaczego

- **Wybrane:** group-by na **istniejącej** liście `GET /api/v1/carrier-inquiries?group_by=` (`party` \| `country` \| `status` \| `thread`). Default `party`. Zero nowej tabeli, zero migracji.
- **Wybrane:** `thread` = para `origin_port_id|destination_port_id` (wątek RFQ / lane z O3). Nie rfc822. Pola już na `carrier_inquiry`.
- **Wybrane:** `party` / `country` z JOIN `network_member` × `party` (jak O7) — odczyt, nie kolumny na inquiry. Odpowiedź listy: opcjonalne `party_id` + `country_code`.
- **Wybrane:** saved view = istniejący `POST /tenancy/table-views` z `table_key=carrier_inquiry` i `config.group_by`. UI na `/networks` (sekcja zapytań). Allowlista `table_view` **dopuszcza** `thread` (142.0 odrzucało — tu buy-desk).
- **Odrzucone:** nowy czat / drugi Outlook (`REJECTED` — PLAN + audyt).
- **Odrzucone:** nowa tabela wiadomości / kolumny `rfc822_message_id` / `in_reply_to` (`REJECTED` na tym wierszu — leftover poczty).
- **Odrzucone:** float / marża / live HTTP / Temporal / Graph (`REJECTED`).
- **Odrzucone:** import `PartyService` / `NetworkService` w BC inquiry (`REJECTED` — JOIN modeli w repozytorium).

**Łowca:** ISTNIEJE `/networks` + lista `carrier_inquiry` (`frontend/src/features/networks/catalog-page.tsx`). ISTNIEJE `table_view` + ViewManager (0.6). ISTNIEJE group_by poczty `/mail` (142.0, bez `thread`). BRAK group_by na buy-desk zapytań. BRAK rfc822 na `inbound_message`.
