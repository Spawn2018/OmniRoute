## Wybrane / odrzucone / dlaczego

**Wybrane (węższe z G2.6–G2.18):** jedna tabela `tender_playbook` per tenant — **twierdzenie playbooka z `source_ref`**, nie extract RFP HITL i nie win/loss. Wiersz = `tender_id` (FK tenanta do `tender`) + `claim_code` (snake 2–32) + `claim_text` (1–512) + `source_ref` (`tenant:manual` albo `fixture://tender-playbook/…`). Operator wpisuje tezę; serwis nie woła LLM i nie czyta `charge`. Zły kod → 400 (`teza`). Pusty / za długi tekst → 400 (`twierdzenie`). Obce `source_ref` → 400 (`obce`). Unique `(organization_id, tender_id, claim_code)`. GET listy SQL. Serwis nie importuje tenders / charges / quotations / extraction. API składa odczyt nagłówka (`TenderService.get_board`). UI `/tender-playbooks` bez `<Money/>` i bez `sum()` w JS. `SHIPPED_CHARGE_ROUTES["175.0"]` = `/tender-playbooks`. OpenFGA: `can_manage_tender_playbooks`. Migracja `115_tender_playbook`. Marża zostaje na `charge`.

**Łowca:** ISTNIEJE `tender` — nagłówek; **nie** dokładamy tez jako JSON tam. ISTNIEJE `operator_notice` — inbox, nie playbook. ISTNIEJE `mail_draft` — szkic maila, nie twierdzenie przetargu. BRAK `tender_playbook`. BRAK `/tender-playbooks`.

**Odrzucone:**

- Extract RFP HITL (leftover G2.7+; nic z LLM do bazy bez człowieka).
- Prospecting HITL / bid/no-bid / award four-eyes / win/loss / TED / CO₂ / consortium (leftover G2.7–G2.18).
