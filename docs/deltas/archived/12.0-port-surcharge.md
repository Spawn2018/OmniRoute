## Ustalenia

- Żywy ID: **M-18**. Token: `port_surcharge` (GLOSSARY). Archiwum: obiekt opłat portowych warunkowych; funkcje pełnego modułu (dopasowanie do wyceny, live taryfa) — w 12.0 jako **katalog**, nie pipeline.
- Unikat `(organization_id, port_id, code)`. FK złożone do `port(organization_id, id)` jak `terminal`.
- `code`: snake 2–32 `^[a-z][a-z0-9_]{1,31}$`, hyphen → `_`, lowercased — kopia regex w `app.domain.port_surcharge`, **nie** import `app.domain.network` / `customer_sop`.
- `title` 1–128. `applies_when` wymagany tekst po trim, max 512 — opis warunku, nie kod.
- `amount` `Numeric(14,4)` > 0; `currency` CHAR(3) ISO. Para nierozerwalna. Nie float. Nie para buy/sell.
- `source_ref` obowiązkowy; ręczny wpis = `tenant:manual`. Klient **nie** wysyła `source_ref` (`extra=forbid`).
- Nieznany `port_id` = `UnknownPort`. Nieznane extra = `UnknownPortSurcharge`. Konflikt kodu = `PortSurchargeConflict`. Zła kwota/waluta/kod = `InvalidPortSurcharge`.
- `resolve(port_id, code)` dokładne po kodzie, nie luźny tytuł.
- OpenFGA: `can_manage_geography` = member. Brak nowej relacji. Nie `can_manage_charges` — to nie marża.
- RLS FORCE + test izolacji dwóch organizacji.
- Job operatora: `/port-surcharges` — DataTableShell, dodanie (port_id + kod + tytuł + warunek + kwota + waluta). `/ports` — panel extra wybranego portu.
- import-linter: nowy pakiet `app.services.port_surcharges` / `app.repositories.port_surcharges`. Extraction / quotations / charges / rate_lines / parties nie importują tego BC. `extraction-no-rates` dostaje `app.models.port_surcharge`.
- Migracja `023_port_surcharge_rls` (w górę i w dół).
- `just dup` ≤ 3% — własny formularz (kwota + warunek, nie `CatalogCreateForm`).
- Kwoty przez `<Money/>`. LLM nie liczy.

## Schemat

`port_surcharge`: `id`, `organization_id`, `port_id`, `code`, `title`, `applies_when`, `amount`, `currency`, `source_ref`, timestamps.
