## Wybrane / odrzucone / dlaczego

**Wybrane (węższe z P2):** jedna tabela `charge_template` per tenant — **kolekcja kodów opłat + daty ważności jako dane**, nie exclusion GiST i nie T-SQL. Wiersz = `template_code` (snake 2–32) + `charge_code` (token A-Z0-9_ 2–32 z katalogu M-06; FK złożone `(organization_id, charge_code)`) + `valid_from` / `valid_until` (`DATE`, `valid_until >= valid_from`) + `source_ref` (`tenant:manual` albo `fixture://charge-template/…`). Kilka wierszy z tym samym `template_code` = kolekcja. Unikat `(organization_id, template_code, charge_code)` — jeden kod raz w szablonie, nie overlap daterange. Zły `template_code` → 400 (detail zawiera `szablon`). Nieznany albo zły `charge_code` → 400 (detail zawiera `kod`). `valid_until` przed `valid_from` / brak dat → 400 (detail zawiera `ważność`). GET listy SQL. Serwis szablonu odczytuje katalog `charge_codes`, nie importuje charges / rate_cards / rate_lines / quotations. Zero kwoty na tym wierszu. UI `/charge-templates`. `SHIPPED_CHARGE_ROUTES["164.0"]` = `/charge-templates`. OpenFGA: `can_manage_charge_templates`. Migracja `104_charge_template`. Marża zostaje na `charge`.

**Łowca:** ISTNIEJE `charge_code` — katalog tokenu, nie nazwana kolekcja z datami; **nie** rozszerzamy o szablon. ISTNIEJE `party_charge_override` — wyjątek kwoty per `party` + opcjonalne daty; **nie** rozszerzamy (inna oś, ma `amount`). ISTNIEJE `document_checklist_rule` — checklista dokumentów na wycenie, nie kody opłat. ISTNIEJE `rate_card` — warunek + Decimal; leftover P1d daty karty, nie kolekcja kodów. ISTNIEJE `location_zone_member` exclusion GiST — wzorzec leftover P2c, **nie** kopiujemy na opłaty. ISTNIEJE `charge` — jedyna marża. BRAK `charge_template`. BRAK `/charge-templates`.

**Odrzucone:**

- Exclusion / CHECK nakładania daterange jak strefy pocztowe (leftover P2c).
- Druga tabela członków / header–line (leftover P2b — tu kolekcja = wiele wierszy tego samego `template_code`).
- Kwota / waluta / marża na szablonie (zostaje `charge` / `rate_card`).
- Matching GET jak 69.0 (P1b).
- FSC / indeks BAF (P3).
- Kolumny na `charge_code` / `party_charge_override` / `rate_card`.
- Zapis do `charge` / float / T-SQL.
