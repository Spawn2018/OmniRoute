# Plaster 8.0 · M-11 Automatyczne kontakty (`resolve_email`)

**Spec źródłowa:** [docs/spec/parties.md](../../spec/parties.md)  
**Zależy od:** 5.0 `party` + `party_email_domain` · 0.4 OpenFGA · 0.6 DataTableShell

**Status:** Zamknięty `/noc` 2026-09-01. Nie Fala 8.

## Wybrane / odrzucone / dlaczego

**Wybrane (węższe z leftoveru 5.0):** matcher maila na istniejącym katalogu `party_email_domain`. Operator wkleja adres → SQL znajduje kontrahenta po domenie (to, co po `@`). Żywy ID **M-11**. Ten sam BC `app.services.parties` — nie drugi serwis. UI na `/parties`.

**Odrzucone:**

- Nowa tabela / nowy BC — domeny i kontakty już są w 5.0.
- Auto-INSERT `party_contact` z maila — zapis tylko po kliknięciu operatora (jak lookup GUS). Prefill w UI wolno.
- IMAP / skrzynka / Outlook — to M-32 / M-33, nie matcher.
- Portal, `portal_user_id`, kolumny na `party_contact` — archiwalne „M-11 portal” koliduje z żywym M-11; portale parked.
- OpenFGA tuple na wiersz `party` („handlowiec widzi swoich”).
- Denylista `gmail.com` / `wp.pl` — tenant sam decyduje, unikat domeny już jest per org.
- Nadpisanie M-10 `party`, M-08 `charge`, M-12 sieci, M-13 scorecard.

## Zakres

`resolve_email(raw)`: wyciągnij domenę z adresu, dokładny lookup `party_email_domain.domain`, zwróć `party`. Nieznany = `UnknownEmailDomain`. Adres bez `@` albo pusta domena = `InvalidPartyData`. Job operatora: pole „Sprawdź mail” na `/parties`.

## Poza zakresem

M-12 · M-13 · M-14 scoring · M-32 poczta · portal · Auth0 · M-02 · auto-INSERT kontaktu · ExtractionService→parties · LLM czytający skrzynkę

## Ustalenia

- Żywy ID: **M-11**. Token domeny zostaje `party_email_domain`. Archiwum „portal M-11” nie używa numeru M-11 w kodzie (portale parked).
- Wejście: pełny adres `local@domain`. Domena = `normalize_email_domain` już w `app.domain.party`. Local-part nie jest kluczem matcha.
- Lookup dokładny, lowercase; unikat `(organization_id, domain)` z 5.0 ⇒ max jeden `party`.
- Brak nowej migracji, o ile nie trzeba indeksu poza istniejącym unique.
- OpenFGA: istniejące `can_manage_parties` = member. Brak nowej relacji.
- RLS bez zmian — te same tabele, te same polityki.
- import-linter: bez nowego pakietu. Extraction / quotations / charges / rate_lines nadal nie importują `parties`.
- `just dup` ≤ 3% — drugie `ResolveTokenForm` na `/parties`, nie klonować całego katalogu.
- Kwoty i marża nie na tej ścieżce. LLM nie liczy i nie zgaduje kontrahenta.
