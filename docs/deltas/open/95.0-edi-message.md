# Plaster 95.0 · S33 tabela komunikatu EDI (M-39)

**Spec źródłowa:** [docs/spec/edi-message.md](../../spec/edi-message.md) · [docs/PLAN-REALIZACJA.md](../../PLAN-REALIZACJA.md) § Kolejka S33  
**Zależy od:** 90.0 tabela `shipment` · 32.0 tablica `/edi` · 0.3 RLS · 0.4 OpenFGA

**Status:** Zaakceptowany `/noc` 2026-09-03. Ten sam żywy ID **M-39**. Nie F9.1.

## Wybrane / odrzucone / dlaczego

**Wybrane:** tabela `edi_message` per tenant na **zleceniu** (partner = `party` na `shipment`, nie luźna wycena). Operator zapisuje komunikat (`noted` / `outbound` / `other`) z `source_ref`. Wiele wierszy na jedno `shipment`. API składa: odczyt `shipment`, zapis komunikatu. Serwis EDI nie importuje `shipments` / `quotations` / `channel_quotes`. Tablica 32.0 przestaje udawać, że `channel_quote` na lane to komunikat EDI. Wzorzec jak S31. Zero parsera. Zero bajtów. Zero live HTTP.

**Łowca:** ISTNIEJE 32.0 `/edi` + `quotationCarrierInquiries` / `fetchChannelQuotes`. BRAK tabeli `edi_message` / X12 / EDIFACT w modelach. PODOBNE: 93.0 `operational_exception`; 92.0 `shipment_document`. Dwa joby (oferta kanału vs komunikat) = `/channel-quotes` vs `/edi`.

**Odrzucone:**

- Parser X12 / EDIFACT / IFTMIN.
- Live HTTP / VAN / AS2.
- LLM składający treść komunikatu.
- Bajty payloadu na wierszu.
- Komunikat na `quotation` zamiast `shipment`.
- Auto-INSERT przy zapisie zlecenia albo z `channel_quote`.
- Kwota / marża na wierszu.
- F9.1.

## Zakres

1. Migracja `053_edi_message_rls` (po `052_operational_exception_rls`): tabela `edi_message` z RLS ENABLE+FORCE; FK tenanta do `shipment`.
2. `GET/POST /edi-messages` — OpenFGA `can_manage_edi_messages` = member. POST: `{shipment_id, message_kind, source_ref}`. Nieznane zlecenie → 404. Zły kind / pusty ref → 400.
3. UI `/edi`: lista wierszy tabeli + „Zapisz komunikat”. `data-edi-message="board"` zostaje. Lista **nie** idzie z `quotationCarrierInquiries`. `SHIPPED_CHARGE_ROUTES["95.0"]` = `/edi`. Asercje 32.0 bez `x12` / `edifact` / `iftmin` / `CatalogCreateForm` zostają.
4. Test izolacji. `just api-types`. How-to `docs/operator/edi.md`.

- Token: `edi_message` (tabela). How-to: `edi.md`.
- `message_kind` CHECK: `noted` | `outbound` | `other`.
