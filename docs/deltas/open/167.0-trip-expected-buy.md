## Wybrane / odrzucone / dlaczego

**Wybrane (węższe z P5):** **rozszerzenie** istniejącego `trip` o snapshot kosztu kupna jako dane, nie nowa tabela wariancji i nie odczyt `charge`. Przy `status=in_transit` (i przy `completed` niosącym ten sam freeze) wiersz ma `expected_buy_amount` (`Numeric(14,4)` > 0) + `expected_buy_currency` (`CHAR(3)`). Przy `draft` / `planned` / `cancelled` obie kolumny są NULL. POST `in_transit` bez kwoty → 400 (detail zawiera `kwota`). POST `planned` z kwotą → 400 (detail zawiera `snapshot`). Kwota ≤ 0 / float / bool → 400 (`kwota`). GET bez zmian (SQL po statusie). Override `trip_no` = nowy wiersz + `superseded_by` (już jest). Serwis `trips` nie importuje charges / quotations / local_charges. UI zostaje `/shipments` (panel przejazdu). `SHIPPED_CHARGE_ROUTES["167.0"]` = `/shipments`. OpenFGA bez nowej relacji (`can_manage_shipments`). Migracja `107_trip_expected_buy`. Marża zostaje na `charge`. Wariancja leftover.

**Łowca:** ISTNIEJE `trip` — status + flota; leftover T2c freeze kosztu / km; **rozszerzamy** o snapshot, nie nową tabelę. ISTNIEJE `charge` — jedyna marża; **nie** druga kolumna marży i **nie** import z serwisu tripa. ISTNIEJE `cost_to_serve` / `money_cost` — pary bez kwoty; **nie** rozszerzamy. BRAK `expected_buy_amount` na `trip`. BRAK tabeli `trip_cost` / `trip_variance`.
