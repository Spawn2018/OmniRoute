## Wybrane / odrzucone / dlaczego

**Wybrane:** żywy ID **M-33** (token `mail_client`). Wysyłka = operator klika i otwiera **swój** klient poczty. Ta sama tabela `mail_draft`: CHECK `status` ∈ (`draft`, `sent`), kolumna `to_address`. `POST /mail-drafts/{id}/dispatch-mailto` tylko gdy jest **accepted** `operator_decision` (`subject_kind=mail_draft`, `subject_id` = id szkicu). Body: `to_address` + opcjonalny `party_id` (odczyt `blocks_auto`). SOP z `blocks_auto` **nie** blokuje mailto — blokuje auto. Odpowiedź zwraca `mailto:` (adres + body szkicu). OpenFGA: istniejące `can_manage_mail_drafts`. Ekran `/ai`: przycisk „Wyślij w kliencie”. Serwis `mail_drafts` nie woła Graph/SMTP — w pliku serwisu nie ma `smtp` / `graph.microsoft` / `httpx`. API składa decyzję + SOP. LLM nie pisze treści.

**Łowca:** ISTNIEJE 26.0 `mailto:` przy kontakcie na `/mail`. ISTNIEJE 76.0 `mail_draft` status tylko `draft`, bez `to_address`. ISTNIEJE 73.0 `GET /customer-sops/auto-block`. ISTNIEJE 74.0 accept na `mail_draft`. BRAK `dispatch-mailto` / status `sent`. PODOBNE: ingest Graph — tu zapis „wysłane” bez live HTTP.

**Odrzucone:**

- Live Graph / SMTP / IMAP send (brak szyfrowanego sekretu tenanta).
- Auto-send / cron / send bez POST operatora.
- Nowa tabela `mail_send` (status szkicu wystarcza).
- Office.js / manifest.
- F9.1 · Auth0 · portale.
