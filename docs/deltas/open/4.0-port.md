# Plaster 4.0 · M-05 Geografia (`port`)

**Spec źródłowa:** [docs/spec/geography.md](../../spec/geography.md), sekcja 4.0  
**Zależy od:** 0.3 RLS · 0.4 OpenFGA · 0.6 DataTableShell · 1.0 `charge_code` (wzorzec katalogu)

**Status:** Plan zaakceptowany 2026-09-01. Kod tylko w nowej rozmowie + `/plaster`.

## Zakres

Katalog `port` per tenant: ingest z `cristan/improved-un-locodes` (pin SHA przy implementacji), aliasy na wierszu, `resolve` tokenu (DoD: `Gdingen` → `PLGDY`), UI `/ports`. `organization_id` obowiązkowy — archiwalny PK-only / NULL odrzucony.

## Poza zakresem

`location`, `location_zone_member`, `terminal`, World Port Index, OSM, ISPS, podpięcie `rate_line` / `quotation`, Q2 M-10, live fetch GitHub na endpoint, druga tabela aliasów, RapidFuzz / pgvector, `container_type`, Auth0, M-02, Exit Wave FE.

## Ustalenia

- Żywy ID modułu: **M-05** (brak kolizji z żywym M-07/M-08). Archiwalne 1.1/1.2 nie używać.
- Całe M-05 = **4.0 → 4.1 → 4.2**, potem Q2. Nie skakać do M-10 po samym 4.0.
- Źródło seed: `cristan/improved-un-locodes` (współrzędne + aliasy); `datasets/un-locode` = rodowód UNECE w `source_ref`. Pełny UN/LOCODE, nie filtr samych morskich; `is_seaport` z danych.
- Ingest poza requestem HTTP: idempotentny upsert per `(organization_id, unlocode)`. CI = fixture (kilka wierszy + alias Gdingen), bez sieci, bez 670k SQL w git.
- OpenFGA: `can_manage_geography` = `member` (jedna relacja na 4.0–4.2).
- RLS FORCE + test izolacji dwóch orgów. Runtime `omniroute_app` NOBYPASSRLS.
- Aliasy na wierszu (`text[]`), nie osobna tabela. Szukanie w Postgres (`pg_trgm` / GIN OK).
- Port nieoficjalny: `is_official = false`, `source_ref = tenant:manual`.
- `lat`/`lng`: Numeric, nie float.
- Job operatora w tym plastrze: `/ports` (DataTableShell): lista, szukaj, dodaj nieoficjalny, resolve.
