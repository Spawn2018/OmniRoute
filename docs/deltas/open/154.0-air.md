## Wybrane / odrzucone / dlaczego

**Wybrane (węższe z U3):** ta sama tabela `shipment_leg`. Migracja `094_shipment_leg_air_kind` rozszerza CHECK o `air`. Operator na `/air` zapisuje odcinek: `shipment_id` + dwie lokalizacje `unlocode` + `source_ref` + `leg_kind=air`. Port podpięty pod lokalizację musi mieć `airport` w `function_flags` (UN/LOCODE pozycja 4, już w 4.0). Jeden odcinek `air` na zlecenie (unikat org+zlecenie+kind). API składa odczyt shipment + location + port; serwis nogi nie importuje geography. `SHIPPED_CHARGE_ROUTES["154.0"]` = `/air`. OpenFGA: `can_manage_shipment_legs`. POST: `leg_kind` opcjonalny, default `road`.

**Łowca:** ISTNIEJE `shipment_leg` road/rail/china_rail/ocean_lcl. ISTNIEJE `function_flags` z tokenem `airport`. BRAK `leg_kind=air`. BRAK `/air`. BRAK HAWB/MAWB na nodze.
