# Plaster 40.0 · M-47 Księgowość (`bookkeeping`)

**Spec źródłowa:** [docs/spec/bookkeeping.md](../../spec/bookkeeping.md)  
**Zależy od:** 1.0 `charge_code` · 1.2 `charge`

**Status:** Delta zaakceptowana `/noc`. Wolno `/plaster`. Nie Fala 8. LLM nie liczy. Nie nowa tabela.

## Wybrane / odrzucone / dlaczego

**Wybrane (węższe z Fali 6 M-47):** integracja księgowa **nie ma eksportu JPK ani HTTP do ERP**. Operator widzi `charge` z nazwą z katalogu `charge_code` oraz `buy`/`sell` — bez odejmowania i bez pliku. Token `bookkeeping` (UI, nie tabela). Żywy ID **M-47**. 1.0 zostaje katalogiem kodów; 38.0 zostaje tablicą nóg przepływu.

**Łowca:** BRAK `bookkeeping` / JPK / tabeli dekretów. ISTNIEJE: `fetchChargeCodes`, `fetchCharges`, `name` na kodzie, `<Money/>`. PODOBNE: 1.0 katalog kodów; 1.2 `/charges`; 38.0 buy/sell bez nazwy kodu.

**Odrzucone:**

- Tabela dekretów / plan kont / JPK — zgadywanie schematu (CURRENT).
- Plik CSV/XML / HTTP do Comarch — leftover integracji.
- `sell − buy` w JS — to `margin()`.

## Zakres
