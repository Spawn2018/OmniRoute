**Status:** Plan zaakceptowany `/noc` 2026-09-08. Żywe ID **M-20** (extract) + zapis M-19 w warstwie API. Nie O7. Nie F10.

## Wybrane / odrzucone / dlaczego

**Wybrane (węższe z kolejki O6):** kolumna `draft_kind` na istniejącej `extraction_draft`. CHECK: `rate_line` \| `carrier_quote`. Stare wiersze = `rate_line`. Accept HITL zostaje w warstwie API (wzorzec 1.3): `rate_line` bez zmian; `carrier_quote` woła `ChannelQuoteService` i zapisuje ofertę z payloadu (Decimal, `source_ref` ze szkicu). `ExtractionService` nadal nie zapisuje stawek ani ofert. UI `/ai` pokazuje kind. `SHIPPED_CHARGE_ROUTES["140.0"]` = `/ai`. OpenFGA bez nowej relacji (`can_review_extractions`).

**Łowca:** ISTNIEJE `extraction_draft` bez `draft_kind`. ISTNIEJE accept → `rate_line` (1.3). ISTNIEJE zapis `channel_quote` (13.0 / O2). PODOBNE składanie w API, nie w serwisie extract. BRAK kind, BRAK gałęzi accept na ofertę kanału.

**Odrzucone:**

- Wszystkie kindy z wizji (`purchase_invoice`, RFQ, skan) — F10 / X9.
- Zapis `channel_quote` z `ExtractionService`.
- Mutacja `carrier_inquiry` na `answered` (136.0 nie ma UPDATE statusu; leftover osobny).
- Auto-accept. Kwota liczona przez LLM.

## Zakres

1. Migracja `082_extraction_draft_kind`: kolumna + CHECK + default `rate_line`.
2. Gałąź accept API → `channel_quote`. Payload: party, POL/POD, dzień, kwota, waluta, opcjonalne TT.
3. UI `/ai` + `just api-types`. How-to w [ścieżka-pieniędzy.md](../../operator/ścieżka-pieniędzy.md) wtopione.
