## Wybrane / odrzucone / dlaczego

**Wybrane (węższe z G2.7–G2.18):** jedna tabela `tender_win_loss` per tenant — **wynik win/loss z `source_ref`**, nie extract RFP HITL i nie four-eyes. Wiersz = `tender_id` (FK tenanta do `tender`) + `outcome` (`won` | `lost` | `no_bid`) + `reason_code` (snake 2–32) + `source_ref` (`tenant:manual` albo `fixture://tender-win-loss/…`). Operator wpisuje werdykt; serwis nie woła LLM, nie mutuje `tender.status` i nie czyta `charge`. Zły `outcome` → 400 (`wynik`). Zły kod powodu → 400 (`powód`). Obce `source_ref` → 400 (`obce`). Unique `(organization_id, tender_id)` — jeden werdykt na przetarg. GET listy SQL. Serwis nie importuje tenders / charges / quotations / extraction / operator_decisions. API składa odczyt nagłówka (`TenderService.get_board`). UI `/tender-win-losses` bez `<Money/>` i bez `sum()` w JS. `SHIPPED_CHARGE_ROUTES["176.0"]` = `/tender-win-losses`. OpenFGA: `can_manage_tender_win_losses`. Migracja `116_tender_win_loss`. Marża zostaje na `charge`.

**Łowca:** ISTNIEJE `tender.status` (`awarded` / `lost` / `no_bid`) — dana nagłówka; **nie** dokładamy powodu jako JSON tam i **nie** mutujemy statusu z tego plastra. ISTNIEJE `operator_decision` — szyna Akceptuj/Zmień/Odrzuć, nie win/loss. ISTNIEJE `tender_playbook` — teza, nie wynik. BRAK `tender_win_loss`. BRAK `/tender-win-losses`.
