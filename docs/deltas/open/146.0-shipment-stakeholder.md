# Plaster 146.0 · I2 `shipment_stakeholder`

**Spec źródłowa:** [docs/PLAN-REALIZACJA.md](../../PLAN-REALIZACJA.md) § I2 · [karty-pol-fala-i.md](../../analysis/karty-pol-fala-i.md) § I2
**Zależy od:** 28.0 `shipment` · 5.0 `party`
**Status:** Plan zaakceptowany `/noc` 2026-09-08. Nie I3. Nie I4. Nie EXP1.

## Wybrane / odrzucone / dlaczego

**Wybrane (węższe z I2):** jedna tabela per tenant. Wiersz = `shipment_id` + `role` + `party_id` + `source_ref`. Role z karty I2: `shipper` | `consignee` | `origin_agent` | `dest_agent` | `ocean_carrier` | `omni_customs` | `client_customs`. `party_id` obowiązkowy na INSERT. Zmiana party przy tej samej roli = nowy wiersz + `superseded_by`. GET SQL po `shipment_id` (bieżące). Złożone FK `(organization_id, shipment_id)` i `(organization_id, party_id)` jak `cargo_claim` — nie da się podpiąć cudzego zlecenia ani kontrahenta.

UI `/shipments`. `SHIPPED_CHARGE_ROUTES["146.0"]` = `/shipments`. OpenFGA: `can_manage_shipments`. Migracja `086_shipment_stakeholder`.

**Łowca:** ISTNIEJE `shipment` i `party`. ISTNIEJE GLOSSARY `shipment_stakeholder`. ISTNIEJE `party_role_assignment` (role **na kontrahencie**, 132.0) — **inny** agregat, nie rozszerzać. BRAK tabeli stron na zleceniu. BRAK `sold_to_party_id` na shipment (to EXP1).

**Odrzucone:**

- EXP1 `sold_to` / `bill_to` / `ship_to` / `notify` jako kolumny albo role w tym plasterze (karta I2 ich nie ma; `sold_to` = leftover EXP1).
- I3 dispatch / 409 na wysyłkę — flaga/HTTP dispatch = leftover I3; tu `party_id` jest wymagane, więc wiersz bez party nie powstaje.
- I4 `booking_instruction`.
- Import serwisów shipments / parties / charges w tym BC.
- Rozszerzenie `party_role_assignment` o `shipment_id`.
