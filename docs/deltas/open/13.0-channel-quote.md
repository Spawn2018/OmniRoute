## Ustalenia

- Żywy ID: **M-18 już zajęte**. Tu **M-19**. Token: `channel_quote` (nowy w GLOSSARY). Archiwum: stawki live i kanały; w 13.0 jako **katalog oferty**, nie pipeline fetch.
- Unikat `(organization_id, party_id, origin_port_id, destination_port_id, quote_date)`.
- FK złożone do `party(organization_id, id)` i dwa razy do `port(organization_id, id)` jak `quotation` POL/POD.
- Tworzenie wymaga `carrier_profile` dla `party_id`. Brak profilu = `UnknownCarrierProfile` (albo istniejący błąd domeny, jeśli już jest — nie zgaduj nazwy w kodzie; w 13.0 nowy wyjątek, kopia wzorca `UnknownPort`).
- `api_adapter = none` **nie** blokuje ręcznego wpisu — operator może wpisać ofertę z telefonu. Live HTTP i tak leftover.
- `amount` `Numeric(14,4)` > 0; `currency` CHAR(3) ISO. Para nierozerwalna. Nie float. Nie para buy/sell.
- `source_ref` obowiązkowy; ręczny wpis = `tenant:manual`. Klient **nie** wysyła `source_ref` (`extra=forbid`).
- `resolve(party_id, origin_port_id, destination_port_id, on_date)`: SQL `quote_date <= on_date` ORDER BY `quote_date` DESC LIMIT 1; pusto = `UnknownChannelQuote`. Zła kwota/waluta = `InvalidChannelQuote`. Konflikt dnia = `ChannelQuoteConflict`. Nieznany port = `UnknownPort`.
- OpenFGA: `can_manage_rate_lines` = member. Brak nowej relacji. Nie `can_manage_charges`.
- RLS FORCE + test izolacji dwóch organizacji.
- Job operatora: `/channel-quotes` — DataTableShell, dodanie (party_id + POL + POD + data + kwota + waluta), resolve.
- import-linter: `app.services.channel_quotes` / `app.repositories.channel_quotes`. Extraction / quotations / charges / rate_lines / parties nie importują tego BC. `extraction-no-rates` dostaje `app.models.channel_quote`.
- Migracja `024_channel_quote_rls` (w górę i w dół).
- `just dup` ≤ 3% — własny formularz (nie `CatalogCreateForm`).
- Kwoty przez `<Money/>`. LLM nie liczy.
