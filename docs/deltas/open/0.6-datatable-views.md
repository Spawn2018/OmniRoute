# Plaster 0.6 · DataTableShell Golden Standard

**ADR:** docs/adr/0002-frontend-platform-2026.md  
**Spec UX:** docs/_knowledge/tools/002-frontend-platform-2026.md  
**Zależy od:** 0.5 Frontend Shell

## Zakres
- Komponent `DataTableShell` (features/_shared lub components/data-table)
- ColumnEditor: checkbox widoczności + DnD kolejności (@dnd-kit)
- Faceted filters + URL sync
- Density compact/comfortable
- ViewManager: zapisz / wczytaj / import widoku / reset
- Migracja `table_view` + RLS + test izolacji
- API CRUD widoków (OpenFGA: member org)
- Pierwszy consumer: `tenancy.users`
- PostHog: `table_view_saved`, `table_view_applied`, `filter_used`
- **vitest** minimum (regresja ColumnEditor / ViewManager)
- Preferuj uruchomienie **openapi-ts** (spłata długu z 0.5); jeśli nie mieści się — osobny mały plaster zaraz po 0.6

## Poza zakresem
Excel-like cell edit, Ag Grid, export XLSX, shared org views (może 0.7),
cov-fail-under / jscpd w gate (slot jakości), branch protection (B.7), JWT

## Kryteria akceptacji
- [x] Użytkownik zmienia kolumny (show/hide + DnD) i zapisuje widok
- [x] Po odświeżeniu widok wraca z API
- [x] Test izolacji `table_view`
- [x] Virtualizacja gotowa na >500 wierszy (choć seed mniejszy)
- [x] Brak drugiego table engine
- [x] `pnpm test` (vitest) zielone dla DataTableShell

## Uwagi zamknięcia
openapi-ts nadal odroczone (osobny mały plaster / slot kontraktu). JWT poza zakresem.
