# Plaster 5.1 · M-21 wycena z portem i kontrahentem

**Spec źródłowa:** [docs/spec/quotation.md](../../spec/quotation.md)  
**Zależy od:** 2.0 `quotation` · 4.0 `port` · 5.0 `party` · 0.3 RLS · 0.4 OpenFGA · 0.6 DataTableShell

**Status:** Delta zaakceptowana `/noc` 2026-09-01. Wolno `/plaster`. Nie Q4.

## Wybrane / odrzucone / dlaczego

**Wybrane (węższe z kolejki Q3):** trzy FK na istniejącym `quotation` — `origin_port_id` (POL), `destination_port_id` (POD), `party_id`. Lista i filtry w SQL. Kwota nadal wyłącznie INSERT…SELECT z bieżącego `rate_line` (`superseded_by IS NULL`). Jeden ekran `/quotations`.

**Odrzucone:**

- Kolumny portu / kontrahenta na `rate_line` — kolejka każe SQL na **istniejących** stawkach; to byłby drugi wymiar silnika stawek (zakazany przy żywym M-07).
- `party_charge_override` w doborze kwoty — katalog uzgodnień, nie silnik wyceny; 5.0 i CURRENT to zamykają.
- Dwa plastry (najpierw port, potem `party`) — job operatora to jeden formularz wyceny; rozbicie zostawia dziurawy ekran.
- `terminal_id` na wycenie, marża, k6, tuple OpenFGA per wiersz.

## Zakres

Snapshot POL/POD + kontrahent na `quotation`. Filtry listy. Kwota ze stawki, nigdy z requestu / LLM / Pythona.

## Poza zakresem

Q4–Q6 · `party_charge_override` → wycena · kolumny na `rate_line` · `charge.margin()` · k6 · HITL · outbox · ExtractionService→rates/parties · Auth0 · M-02 · portale · Exit Wave FE · leftovery UI ADR-0003 · `kind='terminal'` na `location`.

## Ustalenia

- Żywy ID: **M-21**. Brak kolizji z żywym M-07 `rate_line` / M-08 `charge`.
- Port i kontrahent **nie dobierają stawki**. `QUOTE_FROM_CURRENT_SQL` nadal filtruje tylko `charge_code` + `superseded_by IS NULL`. Trzy UUID wchodzą jako bind z requestu i lądują na wierszu.
- FK złożone, tenant-safe, `ON DELETE RESTRICT`:
  - `(organization_id, origin_port_id)` → `port(organization_id, id)`
  - `(organization_id, destination_port_id)` → `port(organization_id, id)`
  - `(organization_id, party_id)` → `party(organization_id, id)`
- CHECK `ck_quotation_lane_party_complete`: albo wszystkie trzy NULL (wiersze 2.0), albo wszystkie trzy NOT NULL (nowa wycena). Częściowy snapshot = odrzut bazy.
- POST wymaga trójki. Brak / obcy tenant = wyjątek domenowy, nie 500. Istnienie gwarantuje FK, nie import `app.services.parties` ani `app.services.geography` (kontrakt independence).
- Lista: `GET /quotations` z opcjonalnymi `party_id`, `origin_port_id`, `destination_port_id` — `WHERE` w SQL, nie pętla w Pythonie. Indeksy btree `(organization_id, …)` na każdej z trzech kolumn.
- OpenFGA bez zmian: `can_manage_quotations` = `member`. Brak tuple na pojedynczą wycenę.
- RLS FORCE już jest na `quotation`. Test izolacji: tenant A nie czyta wycen B; FK na `party`/`port` obcego tenanta odrzucone przez bazę.
- Job operatora: `/quotations` — DataTableShell z kolumnami POL/POD/`party`; formularz: kod opłaty + picker kontrahenta + dwa pickery portu (osobne `GET /parties` i `GET /ports`, nie przez serwis wyceny). Filtry listy tymi samymi UUID.
- `source_ref` i kwota nadal ze stawki. POST bez `amount`.
- Migracja `016_quotation_port_party` (w górę i w dół).
- Extraction nadal nie zna `quotation` / `rate_line` / `party`.

## Schemat

`quotation` (ALTER): `origin_port_id` UUID nullable, `destination_port_id` UUID nullable, `party_id` UUID nullable; trzy FK złożone; CHECK kompletności trójki; indeksy filtrów.

Pozostałe kolumny 2.0 bez zmian: `charge_code`, `rate_line_id`, `amount` Numeric(14,4), `currency` CHAR(3), `source_ref`, timestamps.
