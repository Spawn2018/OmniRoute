**Status:** Zaakceptowany `/noc` 2026-09-03. Ten sam żywy ID **M-37**. Nie F9.1.

## Wybrane / odrzucone / dlaczego

**Wybrane:** tabela `operational_exception` per tenant na **zleceniu**, nie na wycenie. Operator zapisuje wyjątek (`noted` / `blocked` / `other`) z `source_ref`. Wiele wyjątków na jedno `shipment`. API składa: odczyt `shipment`, zapis wyjątku. Serwis wyjątków nie importuje `shipments` / `quotations` / `geography`. Tablica 30.0 przestaje udawać, że wycena bez POL/POD to wyjątek operacyjny. Wzorzec jak S30 (zapis na istniejącym `shipment`). Mapa zostaje poza initial JS (ADR-0003).

**Łowca:** ISTNIEJE 30.0 `/exceptions` + `quotationOperationalExceptions` / `fetchQuotations` + 90.0 `shipment`. BRAK tabeli `operational_exception` / hold / AIS w modelach. PODOBNE: 92.0 `shipment_document`; 91.0 `tracking_event`. Dwa joby (oferta vs wyjątek) = `/quotations` vs `/exceptions`, jedna tabela wyjątków. `party_charge_override` to inny byt.

**Odrzucone:**

- Filtr wycen bez POL/POD jako „wyjątek” — PLAN S31: nie ten filtr.
- Hold / ETA liczona / AIS / project44 / mapa / leaflet / Watchtower — S32.
- `shipment_leg`.
- Wyjątek na `quotation` zamiast `shipment`.
- Auto-INSERT przy zapisie zlecenia albo z brakującego lane.
- Klasyfikacja przez LLM.
- Kwota / marża na wierszu.
- F9.1.

## Zakres

1. Migracja `052_operational_exception_rls` (po `051_shipment_document_rls`): tabela `operational_exception` z RLS ENABLE+FORCE; FK tenanta do `shipment`.
2. `GET/POST /operational-exceptions` — OpenFGA `can_manage_exceptions` = member. POST: `{shipment_id, exception_kind, source_ref}`. Nieznane zlecenie → 404. Zły kind / pusty ref → 400.
3. UI `/exceptions`: lista wierszy tabeli + „Zapisz wyjątek”. `data-operational-exception="board"` zostaje. Lista **nie** idzie z `quotationOperationalExceptions`. `SHIPPED_CHARGE_ROUTES["93.0"]` = `/exceptions`. Asercje 30.0 bez `eta` / `ais` / leaflet / mapbox / `CatalogCreateForm` zostają.
4. Test izolacji. `just api-types`. How-to `docs/operator/wyjatek.md`.
