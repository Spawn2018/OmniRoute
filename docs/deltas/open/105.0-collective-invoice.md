# Plaster 105.0 · S43 zbiorcza faktura (M-91)

**Spec źródłowa:** [docs/spec/collective-invoice.md](../../spec/collective-invoice.md) · [docs/PLAN-REALIZACJA.md](../../PLAN-REALIZACJA.md) § Kolejka S43  
**Zależy od:** 96.0 `sales_invoice` · 90.0 `shipment` · 33.0 tablica `/invoices` · 0.3 RLS · 0.4 OpenFGA

**Status:** Zaakceptowany `/noc` 2026-09-03. Żywy ID **M-91** (wpinka archiwum; nie nadpisuje M-40). Nie F9.1.

## Wybrane / odrzucone / dlaczego

**Wybrane:** tabela `collective_invoice` per tenant. Operator zapisuje, że ta faktura obejmuje **dodatkowe** zlecenie (`sales_invoice_id` + `shipment_id` + `source_ref`). Kotwica zostaje na `sales_invoice.shipment_id`. Kwoty zostają na `charge`. API składa: odczyt faktury, odczyt zlecenia-kotwicy, odczyt dodatkowego zlecenia, zapis wiersza. Serwis zbiorczej nie importuje `sales_invoices` / `shipments`. Wiele dodatkowych zleceń na jedną fakturę. Unikat pary `(organization_id, sales_invoice_id, shipment_id)`. To samo `party_id` na kotwicy i dodatkowym zleceniu — inaczej 400. Wzorzec jak S42. `get_invoice` i `get_shipment` już są. Ekran zostaje `/invoices` (OPS_JOBS = 50).

**Łowca:** ISTNIEJE 96.0 `sales_invoice` (wymagane `shipment_id`, wiele FV na jedno zlecenie = zaliczka). ISTNIEJE 90.0 `shipment` z `party_id` i `uq_shipment_org_id`. ISTNIEJE 97.0 KSeF na tym samym `/invoices`. BRAK tabeli zbiorczej / członka FV+zlecenie. PODOBNE: 98.0 `quote_invoice_settlement` (wycena+faktura, nie drugie zlecenie). Dwa joby (wystaw FV vs dopisz zlecenie do FV) = ten sam ekran, druga akcja jak 97.0. Płatność paczką po wielu FV = nie ten plaster (`bank_payment` zostaje para 1:1).

**Odrzucone:**

- Nowa trasa `/collective-invoices` — OPS_JOBS ma zostać długości 50.
- Nullable `sales_invoice.shipment_id` i many-to-many zamiast kotwicy.
- Jedna płatność na wiele faktur — to nie zbiorcze FV; `bank_payment` zostaje.
- Zaliczka / druga FV na to samo zlecenie — już 96.0.
- Kwota / JPK / PDF / live KSeF.
- F9.1.

## Zakres

1. Migracja `063_collective_invoice_rls` (po `062_bookkeeping_rls`): tabela `collective_invoice` z RLS ENABLE+FORCE; FK tenanta do `sales_invoice` i `shipment`.
2. `GET/POST /collective-invoices` — OpenFGA `can_manage_collective_invoices` = member. POST: `{sales_invoice_id, shipment_id, source_ref}`. Nieznana faktura albo zlecenie → 404. To samo zlecenie co kotwica faktury → 400. Inny `party_id` niż kotwica → 400. Pusty / obcy `source_ref` → 400.
3. UI `/invoices`: lista członków + „Zapisz zbiorczą”. `data-sales-invoice="board"` zostaje. „Zapisz fakturę” i KSeF zostają. Lista członków **nie** idzie z `fetchCharges`. `SHIPPED_CHARGE_ROUTES["105.0"]` = `/invoices`. OPS_JOBS długość 50 (bez nowej trasy).
4. Test izolacji. `just api-types`. How-to `docs/operator/zbiorcza-faktura.md`.
