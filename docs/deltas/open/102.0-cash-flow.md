# Plaster 102.0 · S40 przepływy (M-45)

**Spec źródłowa:** [docs/spec/cash-flow.md](../../spec/cash-flow.md) · [docs/PLAN-REALIZACJA.md](../../PLAN-REALIZACJA.md) § Kolejka S40  
**Zależy od:** 2.0 `quotation` · 99.0 `bank_payment` · 38.0 tablica `/cashflows` · 0.3 RLS · 0.4 OpenFGA

**Status:** Zaakceptowany `/noc` 2026-09-03. Ten sam żywy ID **M-45**. Nie F9.1.

## Wybrane / odrzucone / dlaczego

**Wybrane:** tabela `cash_flow` per tenant. Operator zapisuje, że ta wycena ma ruch pieniądza w tej płatności (`quotation_id` + `bank_payment_id` + `source_ref`). Kwoty zostają na `charge` (`buy` = wypływ, `sell` = wpływ). Tablica 38.0 przestaje udawać, że lista nóg z `charge` to księga. API składa: odczyt wyceny, odczyt płatności, zapis wiersza. Serwis przepływu nie importuje `quotations` / `bank_payments` / `charges`. Wiele wierszy na jedną wycenę (kolejne płatności). Unikat pary `(organization_id, quotation_id, bank_payment_id)`. Wzorzec jak S39. `get_quotation` i `get_payment` już są.

**Łowca:** ISTNIEJE 38.0 `/cashflows` + `cashFlowLegs` / `fetchCharges` / `buy_amount` / `sell_amount`. ISTNIEJE 2.0 `quotation` z `uq_quotation_org_id`. ISTNIEJE 99.0 `bank_payment` z `uq_bank_payment_org_id` i `get_payment`. BRAK tabeli `cash_flow` / `ledger` / księgi. PODOBNE: 101.0 `fx_difference`; 98.0 `quote_invoice_settlement` (wycena+faktura, nie płatność). Dwa joby (opłata vs przepływ) = `/charges` vs `/cashflows`. `ChargeService` nie ma `get` — para opłata+płatność wymagałaby nowego odczytu na M-08.

**Odrzucone:**

- Zostawić tablicę `buy`/`sell` z `charge` — to fundament 38.0, nie żywe M-45.
- `sell − buy` w JS albo w Pythonie — to `margin()`.
- Kolumna kwoty / `buy` / `sell` na wierszu przepływu.
- Para `charge` + płatność — `ChargeService` nie ma `get`; `uq_charge_org_id` nie istnieje; M-08 zostaje nienaruszone.
- Para faktura + płatność — już jest na `bank_payment.sales_invoice_id`.
- DSO / dopasowanie wyciągu.
- F9.1.

## Zakres

1. Migracja `060_cash_flow_rls` (po `059_fx_difference_rls`): tabela `cash_flow` z RLS ENABLE+FORCE; FK tenanta do `quotation` i `bank_payment` (oba mają już unikat org+id).
2. `GET/POST /cash-flows` — OpenFGA `can_manage_cash_flows` = member. POST: `{quotation_id, bank_payment_id, source_ref}`. Nieznana wycena albo płatność → 404. Pusty / obcy `source_ref` → 400.
3. UI `/cashflows`: lista wierszy tabeli + „Zapisz przepływ”. `data-cash-flow="board"` zostaje. Lista **nie** idzie z `fetchCharges` ani `cashFlowLegs` na tablicy. Linki do `/quotations` i `/payments` zostają. `SHIPPED_CHARGE_ROUTES["102.0"]` = `/cashflows`. Asercje 38.0 bez `parseFloat` / odejmowania / `CatalogCreateForm` zostają; helper `cashFlowLegs` zostaje w `charges-api` (test jednostkowy 38.0), nie na tablicy.
4. Test izolacji. `just api-types`. How-to `docs/operator/przeplywy.md`.

## Ustalenia

- Token: `cash_flow` (tabela). How-to: `przeplywy.md`.
- `source_ref`: `fixture://cash-flow/` albo `tenant:manual`. Pusty po trim = 400. Max 256.
- Serwis bez `httpx` / `requests`. ExtractionService nie importuje przepływów.
- LLM nie liczy. `charge` zostaje prawdą o marży. HITL extract bez zmian.
- Formularz: siatka dwóch kolumn (`grid-cols-2`). Nie `CatalogCreateForm`, nie `divide-y` z 101.0, nie `fieldset` z 99.0, nie `border-l-2` z 100.0, nie `flex max-w-xl` z 98.0 (próg `just dup` 3%).
- OPS_JOBS zostaje długości 50 (ta sama trasa; etykieta jobu: zapis przepływu wyceny przy płatności).

## Schemat

`cash_flow` (nowa): `id`, `organization_id`, `quotation_id`, `bank_payment_id`, `source_ref`, timestamps, `created_by`. FK tenanta do obu rodziców. Unikat org+wycena+płatność.
