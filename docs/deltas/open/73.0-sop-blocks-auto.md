## Wybrane / odrzucone / dlaczego

**Wybrane:** ta sama tabela `customer_sop`. Kolumna `blocks_auto` BOOLEAN NOT NULL, default `true` (SOP = człowiek, nie automat). Flaga wchodzi przy tworzeniu draftu i zamarza przy `approve` — zatwierdzonej nie edytuje się w miejscu (11.0). Odczyt dla przyszłego send: SQL `EXISTS` zatwierdzonej SOP z `blocks_auto` u tego `party_id`. Endpoint `GET /customer-sops/auto-block?party_id=`. OpenFGA bez nowej relacji: `can_manage_parties`. Ekran: ten sam `/customer-sops` (checkbox). Serwis SOP nie importuje inbound / quotations / mail. Zero send.

**Łowca:** ISTNIEJE: `customer_sop` draft/approved, `approve`, `resolve(party_id, code)`, UI `/customer-sops` + panel `/parties`, RLS FORCE, `can_manage_parties`. PODOBNE: 11.0 `approved_at` para ze statusem. BRAK: `blocks_auto`; odczyt „czy ten kontrahent blokuje auto”; checkbox.
