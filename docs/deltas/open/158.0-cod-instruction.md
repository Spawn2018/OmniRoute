**Status:** Delta zaakceptowana `/noc` 2026-09-08. Nie kwota. Nie Fala F.

## Wybrane / odrzucone / dlaczego

**Wybrane (węższe z D4):** jedna tabela `cod_instruction` per tenant — **znacznik pobrania na zleceniu**, bez kwoty. Rozliczenie pobrań = Fala F (`charge` zostaje prawdą o marży). Wiersz = `instruction_code` (snake 2–32) + FK złożone do `shipment` + `collection_status` (`noted` | `advised` | `collected` | `refused`) + `source_ref`. `collected` to status operacyjny, nie zapis pieniędzy. GET listy SQL. API składa odczyt `shipment`; serwis COD nie importuje shipments / charges / sales_invoices. UI `/cod`. `SHIPPED_CHARGE_ROUTES["158.0"]` = `/cod`. OpenFGA: `can_manage_cod_instructions`. Migracja `098_cod_instruction`.

**Łowca:** ISTNIEJE `shipment_document` (`noted`/`attached`/`other`) — wskazanie dokumentu, nie pobranie. ISTNIEJE GLOSSARY `POD` = `destination_port_id` — **inny** byt niż proof of delivery. ISTNIEJE `bank_payment` / `sales_invoice` — płatność i FV, nie COD. BRAK `cod_instruction`. BRAK `/cod`. BRAK statusu pobrania bez kwoty.

**Odrzucone:**

- Kwota / Decimal / rozliczenie pobrania (Fala F).
- POD/ROD jako `document_kind` na `shipment_document` (leftover D4b; `pod` koliduje z portem wyładunku; kind ma 16 znaków).
- Bajty skanu POD / kamera.
- Live HTTP / marża / druga tabela pieniędzy.
