**Status:** Zaakceptowany `/noc` 2026-09-03. Ten sam żywy ID **M-48**. Nie F9.1.

## Wybrane / odrzucone / dlaczego

**Wybrane:** jedna tabela `shipment_leg` per tenant (GLOSSARY: odcinek). Operator na `/road` **zapisuje** odcinek drogowy: `shipment_id` + `origin_location_id` + `destination_location_id` + `source_ref`. `leg_kind = road` (CHECK). Lokalizacje `postal_zone` albo `address` — nie `unlocode` (to port). Jeden odcinek `road` na zlecenie. API składa: odczyt `shipment`, odczyt dwóch `location` (`get_location` na geography, jeśli brak), zapis nogi. Serwis nogi nie importuje `shipments` / `geography`. Tablica 41.0 przestaje udawać, że droga to sama lista stref. `SHIPPED_CHARGE_ROUTES["108.0"]` = `/road`. OPS_JOBS długość 50.

**Łowca:** ISTNIEJE 41.0 `/road` + `roadLocations` + `fetchLocations`. ISTNIEJE 90.0 `shipment` + `uq_shipment_org_id`. ISTNIEJE 4.1 `location` + `uq_location_org_id`. BRAK `shipment_leg` / `road_leg` w modelach. PODOBNE: 105.0 para na istniejącym ekranie. Dwa joby (katalog lokalizacji vs odcinek na zleceniu) = `/locations` vs `/road`.

**Odrzucone:**

- Druga mapa / leaflet / GPS / ETA — PLAN: nie druga mapa.
- TMS / naczepa / flota (S50).
- Osobna tabela `road_leg` — kanon to `shipment_leg`.
- `leg_kind` rail / china_rail / ocean_lcl — S47–S49.
- Kwota / marża / kopia `charge`.
- Auto-INSERT przy zapisie zlecenia.
- F9.1.
