Dlaczego mockup jest niedokończony

świadomy stan · nie niedoróbka grafika · nie drugi frontend

1. Produkt w kodzie jest fundamentem tablic, nie wieżą operacyjną

Audyt 2026-09-02: 27 tablic-odczyt, 8 nakładek na /quotations, 18 katalogów z tabelą.

Żywe Zlecenia to ~40 linii: filtr wycen z party_id, link do /quotations, podtytuł „nie tabela · nie tracking”. Żywe Wyceny to najgęstszy ekran (tabela DataTableShell + panele NBP / ryzyko / dokument / pending) — nadal jedna tabela quotation, bez PDF, bez won/lost, bez skrzynki.

2. Fala S dopiero zdejmuje „nie X”

CURRENT: po 64.0 S1; następny S2 resolve_email na inbound_message

Tabela shipment = S28. Watchtower = S32. Mapa = lazy chunk, nie initial JS (ADR-0003). Ten plik pokazuje duch celu, nie zaimplementowany S32.

3. Tablice-odczyty nie idą na notę 5,0

PLAN § Cel jakości

Makieta nie dorysowuje KSeF, IMAP, Office.js ani giełdy. Szare pozycje w nav to wizja / tablica. Kwoty poniżej są literalnym stringiem — ten HTML nie sumuje w JS (HC-02).

4. To artefakt dla Claude, nie plaster UI

docs/design/ · nie bundel Vite · nie frontend/src

Nie zastępuje ADR-0003 ani leftoverów U-oklch-dark / U-print. Nie wolno wklejać tego HTML do aplikacji jako „gotowy ekran”.

5. Czego tu celowo nie ma

żeby Claude nie wziął makiety za zakres S1

  • brak mapy (własny budżet chunka)
  • brak accept HITL (optimistic zakazany)
  • brak liczenia marży w przeglądarce
  • brak portalów M-61…67
